# Deploy Mair's Trivia on Render

## Before you deploy

1. Open [KeiJoi/mairstrivia](https://github.com/KeiJoi/mairstrivia), then fork it to deploy your own copy (or clone it if you will push to an existing repository).
2. Sign in to [Render](https://render.com/) and create a **Blueprint** deployment.
3. Connect GitHub, select the repository, and use the root `render.yaml` Blueprint.

The Blueprint creates one paid Starter Node web service. A persistent disk cannot be attached to a free service and cannot be shared by multiple service instances, so the service intentionally uses one instance.

## Required settings

During initial Blueprint creation, Render asks for values marked `sync: false`:

- `SERVER_ACCESS_PASSWORD`: a long, unique deployment password. This controls deployment access only; it is not a host account password.
- `PUBLIC_BASE_URL`: the exact public HTTPS URL Render assigns, for example `https://mairs-trivia.onrender.com`. Do not include a trailing slash.

`TOKEN_SECRET` is generated by Render. Do not replace it during normal redeploys, because doing so invalidates active host sessions. No real secret is committed to the Blueprint.

Click **Apply** and deploy. The service runs `npm ci`, then starts its Node server. At runtime—after Render mounts the disk—the application creates `/var/data/trivia.sqlite`, enables SQLite WAL mode, and applies pending tracked migrations before listening. If migration fails, startup fails instead of serving with an unknown schema.

Wait for `https://YOUR-SERVICE/health` to return JSON with `status: "ok"`. Render terminates TLS at its public HTTPS URL; WebSocket clients use the corresponding `wss://` endpoint automatically.

## Connect the plugin

In Mair's Trivia, open `/mairstrivia`:

1. Enter the public HTTPS service URL as the Backend URL.
2. Enter the deployment server password.
3. Create a host account or log in with an existing one.
4. Confirm the displayed health/login status, then create a game. Player clients reconnect through the backend WebSocket endpoint.

The plugin stores a revocable refresh credential, not the raw host password. The server password is only held in memory for the current plugin session.

## Persistence, backups, and updates

Only `/var/data` is persistent. The SQLite database is always `/var/data/trivia.sqlite`; never change production `DATABASE_PATH` to a location outside that mount. Render disks are available only at runtime, not during build or pre-deploy commands, which is why migrations run on application startup.

Render persistent disks have automatic daily snapshots. Use Render's disk restore/snapshot controls for high-level recovery, and periodically download/export any operational data you need according to your backup policy. A disk is tied to one service instance; do not scale this SQLite deployment horizontally.

To update, push to the connected branch or trigger a manual deploy in Render. The next process start applies any pending short, transactional migrations against the mounted database. Review the deployment logs and `/health` after every update.

## Local development

Install Node.js 24 LTS, then run:

```powershell
cd server
Copy-Item .env.example .env
npm ci
npm start
```

Set strong local values for `SERVER_ACCESS_PASSWORD` and `TOKEN_SECRET`; never commit `.env`. The default development database path is `server/data/mairs-trivia.db`. Run `npm test` and `npm run build` before deploying.
